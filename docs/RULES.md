# RULES — 하드룰 (규칙의 단일 출처)

다른 문서는 이 번호와 요지만 가리킨다. 본문은 여기에만 쓴다.
규칙마다 **무엇이 막는지**를 함께 적는다. 막는 장치가 없는 규칙은 '사람 확인'으로 표시하고, 장치를 만들 대상으로 `STATE.md` 열린 질문에 올린다.
훅·검사기와 이 문서가 다르면 코드가 맞다. 차이를 발견하면 알리고 같은 커밋에서 맞춘다.

| # | 규칙 | 막는 것 |
| --- | --- | --- |
| 1 | **원장은 append-only TSV, 코드가 쓴다.** 기존 행을 고치거나 지우지 않는다. 정정도 새 행이다. 실패한 run 도 `status=fail` 로 남긴다 | pre-commit (`validate_ledger`), CI |
| 2 | **결과 기록(`record`)과 코드 변경은 다른 커밋이다.** 해시를 손으로 적지 않는다. `fix` 는 무효가 된 run 을 `Invalidates` 로 적는다 | commit-msg 훅, CI |
| 3 | **lockbox 는 git 밖에 두고 열지 않는다.** 확증 단계 전용 자료(무엇을 넣을지는 Gate 2.5 에서 정함)는 `lockbox/` 에 두고, 연 시점은 태그 `lockbox-opened` 로 남긴다 | pre-commit (경로에 `lockbox`), `.gitignore` |
| 4 | **사전등록 이후에는 기준을 바꾸지 않는다.** Gate 2.5 에서 가설·지표·분석 코드·$S_{\max}$·일정을 동결하고 태그 `prereg-v1` 을 붙인다. 이후 변경은 모두 `docs/deviation_log.md` 에 쓴다. Gate 2.5 이전 실행(P0~P1)은 탐색 데이터로, 주 가설 판정에 쓰지 않는다 (기획서 §17) | 태그 + 사람 확인 |
| 5 | **조율은 Validation 으로만 한다.** 아키텍처마다 같은 수의 하이퍼파라미터 시도(동일 탐색 예산), 같은 분할 Seed, 같은 최대 스텝·평가 간격·정밀도 (기획서 §12A-4). Test 지표로 설정을 고르지 않는다 | 사람 확인 |
| 6 | **비교는 한 변수만.** 비교 묶음은 아키텍처 · ρ · Router · Seed 흐름 중 의도한 것 하나만 다르다. 중앙값·표준편차·반복 수를 보고하고, Seed 간 변동보다 작은 차이는 "차이 미확인"이다 | 사람 확인 (PR 체크리스트) |
| 7 | **Seed 흐름 네 개를 나눠 기록한다.** `split_seed`(고정 1개) · `init_seed` · `mask_seed` · `order_seed` (기획서 §12A-5) | 원장 열 (`validate_ledger`) |
| 8 | **데이터는 생성 규칙과 해시로 재현한다.** 기본은 무작위 순서쌍 분할, 입력 `a b =` 3토큰 (기획서 §7.1.1). 데이터 파일은 커밋하지 않는다 | pre-commit (`data/`), Gate 1 pytest |
| 9 | **Logits · Softmax · Loss 는 FP32 로 계산한다** (기획서 §14, [25]) | Gate 3 정밀도 점검 |
| 10 | **대용량 산출물은 git 밖.** 체크포인트·가중치·지표 Parquet·Activation 은 커밋하지 않는다. 파일 하나 5MB 상한 (기획서 §15.2) | pre-commit, `.gitignore` |
| 11 | **훅을 우회하거나 검증을 약하게 고치지 않는다.** `--no-verify`, 테스트·허용 범위·판정 기준 완화 금지. 같은 원인으로 검증이 2번 실패하면 멈추고 사람에게 알린다 | CI 백스톱 + 사람 확인 |
| 12 | **비밀값을 파일·로그·커밋에 쓰지 않는다.** 예시는 `.env.example` 에 이름만 | `.gitignore` (`.env`, `.secrets/`) |
| 13 | **탐색 예산을 지킨다.** 같은 접근이 3회 연속 개선이 없으면 닫는다. 예산 소진은 성공이 아니다 | 사람 확인 |
| 14 | **원본을 덮어쓰지 않는다.** 원시 결과·체크포인트는 보존하고, 산출물은 해시와 생성 레시피로 잇는다 | 사람 확인 |
