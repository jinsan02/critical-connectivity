# 함께 삽질 기록 (사람 + AI 에이전트)

[`TROUBLESHOOTING.md`](TROUBLESHOOTING.md)에는 시스템 문제를 적는다. 여기에는 **사람과 AI 에이전트(Claude Code · Codex)가 같이 일하면서 생긴 헛수고 · 착각 · 소통 문제**를 적는다.
나중에 블로그(velog)에 쓸 재료다. 항목마다 상황 → 무엇이 틀렸나 → 어떻게 알아챘나 → 교훈 순으로 쓰고, 숫자와 커밋은 사실 그대로 적는다. AI 의 잘못도 숨기지 않는다.

## C-009 "이 프젝도 … 전꺼처럼" 에서 대상 저장소를 거꾸로 읽음

- **상황**: Gate 1 모델 구현 도중 사용자가 "이 프젝도 gh repo clone jinsan02/strata-local-llm, 이거 전꺼처럼 트러블슈팅이랑 삽질하는거 문서관리하자" 라고 보냈다.
- **무엇이 틀렸나**: Claude 는 strata-local-llm 을 **새로 문서 체계를 세울 대상**으로 읽었다. 진행 중이던 모델 작업을 다른 세션에 넘기고, '전꺼' 의 형식을 찾으려고 다른 프로젝트 폴더 7곳을 뒤졌다. 실제 뜻은 반대였다. strata-local-llm 이 '전꺼' 이고(이미 TROUBLESHOOTING T-001~ 과 COLLAB-LOG C-001~ 을 운영), 대상은 이 저장소였다.
- **어떻게 알아챘나**: 다른 세션의 메모리에서 strata 항목을 열자 `docs/COLLAB-LOG.md` · `TROUBLESHOOTING.md` 운영 기록이 나왔다.
- **교훈**: 사용자가 저장소 이름을 대면 그 저장소의 메모리와 `docs/` 부터 본다. 주변 폴더를 넓게 뒤지는 것보다 빠르고 정확하다. 모델 작업을 넘긴 것 자체는 손해가 없었다(병렬로 진행).

## C-008 Python `write_text` 가 Windows 에서 CRLF 로 씀

- **상황**: 테스트 파일 두 개를 Python 스크립트(`Path.write_text`)로 고쳐 본체에 복사하고 커밋했다.
- **무엇이 틀렸나**: Windows 의 텍스트 모드 쓰기는 `\n` 을 `\r\n` 으로 바꾼다. 원래 LF 였던 파일이 CRLF 가 됐다.
- **어떻게 알아챘나**: `git add` 가 `CRLF will be replaced by LF the next time Git touches it` 경고를 냈다. 커밋된 내용은 git 이 LF 로 정규화해 문제가 없었다.
- **교훈**: Windows 에서 Python 으로 저장소 파일을 쓸 때는 `newline="\n"` 을 준다. `.ps1` 은 반대로 BOM 이 필요하다(T-006).

## C-007 "CI 에서 해시가 재현됐다" 고 보고했는데, 그 테스트는 돌지 않았다

- **상황**: PR #1(데이터 생성 · 분할)을 올리고 "Ubuntu CI 에서 같은 해시가 재현됐으니 어느 PC 에서든 같은 분할이 나온다" 고 보고했다. PR 은 이 보고 뒤에 CI 초록으로 머지됐다.
- **무엇이 틀렸나**: 분할 설정 3개가 `.gitignore` 의 `data/` 에 걸려 커밋되지 않았다(T-008). CI 의 해시 재현 테스트는 빈 parametrize 로 **skip** 됐고, CI 는 초록이었다. 'CI 통과' 를 '해시 재현 확인' 으로 바꿔 읽었다.
- **어떻게 알아챘나**: 머지 뒤 본체에서 verify 를 돌리니 `29 passed, 1 skipped`. skip 하나가 걸려 `pytest -rs` 로 이유를 봤다.
- **교훈**: 통과 보고에는 skip 수를 같이 적고, skip 이 있으면 이유를 본다. "X 가 확인됐다" 고 말하려면 X 를 검사하는 테스트가 **실제로 돌았는지**까지 본다. 빈 입력이면 조용히 넘어가는 테스트는 실패하게 고친다(`test_data_configs_present`).

## C-006 설치 확인 없이 `--extra-index-url` 을 믿음 → GPU 없는 torch

- **상황**: 본체 환경 설치 명령을 Claude 가 `pip install torch --extra-index-url .../cu128` 로 짰다.
- **무엇이 틀렸나**: pip 는 여러 인덱스 중 버전이 높은 쪽을 고른다. PyPI 의 CPU 빌드 2.15.0 이 cu128 의 2.11.0 을 이겼다(T-003). 설치 스크립트는 성공(exit 0)으로 끝났다.
- **어떻게 알아챘나**: 설치 직후 확인 출력이 `2.15.0+cpu None False`.
- **교훈**: '설치 성공' 은 '쓸 수 있음' 이 아니다. 설치 스크립트 마지막에 이 프로젝트가 꼭 필요한 성질(`torch.cuda.is_available()`)을 assert 한다. 특수 빌드는 `--index-url` 하나만 쓰고 로컬 버전 태그(`+cu132`)까지 고정한다.

## C-005 force push 차단을 `--dry-run` 으로 확인하려 함

- **상황**: main ruleset(삭제 · force push 금지)을 만든 뒤 실제로 막히는지 확인하려고 `git push --force --dry-run` 을 생각했다.
- **무엇이 틀렸나**: dry-run 은 서버에 아무것도 보내지 않는다. GitHub ruleset 은 서버에서 판정하므로 dry-run 결과는 규칙과 상관없이 나온다. 진짜 force push 는 main 을 망가뜨릴 수 있어 시험할 수 없다.
- **어떻게 알아챘나**: 결과를 해석하기 전에 dry-run 이 무엇을 검사하는지 따져 보다가.
- **교훈**: 서버 규칙은 서버에 물어본다. `gh api repos/<owner>/<repo>/rules/branches/main` 으로 그 브랜치에 실제로 걸린 규칙을 확인했다. "확인했다" 는 말은 그 확인 방법이 실패를 잡을 수 있을 때만 쓴다.

## C-004 백슬래시 경로가 든 줄을 sed · perl · awk 로 고치다 실패

- **상황**: 문서에 든 Windows 경로(`C:\...`)를 Git Bash 의 sed · perl · awk 로 바꾸려 했다.
- **무엇이 틀렸나**: 백슬래시가 셸 → 정규식 → 바꿀 문자열 층을 지나며 매번 다르게 풀렸다. strata-local-llm 의 C-007 · C-028 과 같은 종류다.
- **어떻게 알아챘나**: 치환이 안 되거나 엉뚱한 글자가 들어갔다.
- **교훈**: 경로 · 한국어가 섞인 치환은 파일 편집 도구로 하거나, PowerShell 의 문자열 `.Replace()`(정규식 아님)로 하고 UTF-8(BOM 없음)으로 저장한다.

## C-003 참고문헌 arXiv ID 를 기억으로 적어 틀림

- **상황**: 11-24 문헌 조사 중에 참고문헌 [24] "Hidden Progress in Deep Learning" 의 arXiv ID 를 적었다.
- **무엇이 틀렸나**: Claude 가 기억으로 2207.08899 라고 적었다. 맞는 값은 2207.08799 다.
- **어떻게 알아챘나**: arXiv 에서 직접 조회해 대조하다가. 저장소에 들어간 문서(기획서 §20, 참고문헌 검증 문서)에는 맞는 값만 있다.
- **교훈**: 식별자(arXiv ID · DOI · 커밋 해시 · 버전)는 기억으로 적지 않고 원문에서 복사한다. 검증 단계를 따로 두는 이유다(`docs/plan/reference_verification_v0.2.md`).

## C-002 PowerShell 변수 `$T` 와 `$t` 가 같은 변수라 0 으로 나눔

- **상황**: 조사 단계에서 PowerShell 스크립트로 합계 `$T` 와 반복 변수 `$t` 를 같이 썼다.
- **무엇이 틀렸나**: PowerShell 변수 이름은 대소문자를 구분하지 않는다. `$t` 가 `$T` 를 덮어 0 으로 나누기 오류가 났다. strata-local-llm 에서 같은 실수를 이미 두 번 기록했다(C-022 · C-028).
- **어떻게 알아챘나**: divide-by-zero 오류.
- **교훈**: PowerShell 에서는 대소문자만 다른 이름을 쓰지 않는다(`$NT` 처럼 아예 다르게). 다른 저장소의 COLLAB-LOG 에 적힌 실수도 이 저장소에서 다시 난다. 원격 스크립트를 쓰기 전에 strata 의 문자열 층 체크리스트를 본다.

## C-001 노트북 Python 이 없어 XML 을 curl · sed · grep 으로 파싱

- **상황**: 신규성 검색에서 arXiv API 응답(XML)을 읽어야 했는데, 노트북의 `python` 은 WindowsApps 별칭뿐이었다(T-001).
- **무엇이 틀렸나**: Python 을 설치하는 대신 curl · tr · sed · grep 으로 XML 을 잘라 읽었다. http 요청이 빈 응답을 내자 https · `-L` 로 바꾸는 우회도 더했다. 우회가 쌓일수록 결과를 믿기 어려워졌다.
- **어떻게 알아챘나**: 다음 날 저장소 훅을 만들면서 같은 문제(python 이 진짜인지 모름)에 다시 부딪혔다.
- **교훈**: 같은 도구 부재로 두 번째 우회를 하게 되면 우회 대신 환경을 고친다. 노트북에도 critconn 을 설치했다(T-006 뒤). strata-local-llm 의 C-004 와 같은 흐름이다.
