# P1 파일럿 설계 — 아키텍처별 하이퍼파라미터 조율

- 작성: 2026-11-27 · 근거: 기획서 v0.6 §9 EXP-01, §12A-4, §12B-5, §15.1 · 상태: 사람 결정 반영, 실행 전
- 대기열: `configs/queue/p1_b1.yaml`(1단계 12회), `configs/queue/p1_rest.yaml`(2단계 72회)

P1 은 **탐색 데이터**다 (기획서 W3 일정표: Gate 2.5 이전 실행은 주 가설 판정에 쓰지 않는다). 목적은 세 가지다.

1. 아키텍처마다 같은 탐색 예산(12회)으로 학습 설정을 하나씩 고른다 (§12A-4 동일 탐색 예산, [30]).
2. 8M · 64M 계열의 초기화 스케일을 정한다 (STATE 열린 질문 12, T-010).
3. Gate 2.5 에서 동결할 $S_{\max}$ 와 중도절단 비율을 가늠한다 (§12B-5).

$1/\sqrt{d}$ 값: $d$=288(B-1 · B-4 · B-5 · B-6 · Cross-Model) 0.0589, $d$=576(B-2) 0.0417, $d$=816(B-3) 0.0350. 초기화 std 는 Adapter · Router 를 포함한 모든 Linear · Embedding 에 같이 걸린다.

**기획서 EXP-01 격자와 다른 점** (사람 결정 2026-11-27):

- weight decay 0.01 을 뺐다. 대신 초기화 스케일을 넣었다. R1 은 init 0.02 로 100K 안에 Grokking 하지 않았고 1/√d 로는 3,300 스텝에 했다 (T-010). Omnigrok [16] 도 초기 가중치 노름을 주 변수로 본다.
- 학습 데이터 비율(30 · 40 · 50%)은 조율하지 않는다. §12A-4 가 모든 실험의 분할을 같게 두라고 하므로 D01 의 40% 로 고정한다.
- 시도마다 Seed 1개다. 고른 설정의 Seed 반복은 P2 이후 본 실험에서 한다.

## 3. 선택 규칙 (아키텍처마다 12회 중 하나)

Validation 곡선만으로 정한다. 정의는 §10.2 와 `src/training/early_stop.py` 를 따른다.

1. **지연 Grokking 후보**: $T_{grok}$ 이 확정됐고 $T_{grok} - T_{mem} \ge 1{,}000$ 스텝인 시도. 처음부터 Train · Val 이 같이 오르는 설정은 임계점 연구에 쓸 암기 → 일반화 전이가 없으므로 뺀다 (§9 EXP-01 마지막 문단).
2. 후보 중 $T_{grok}$ 이 가장 짧은 시도를 고른다. 같으면 최종 Val 정확도가 높은 쪽, 그래도 같으면 시도 번호가 작은 쪽.
3. 후보가 없으면 최종 Val 정확도가 가장 높은 시도를 고르고 **"지연 Grokking 없음"** 으로 표시한다. 이 아키텍처는 Gate 2.5 에서 격자를 넓힐지 사람과 정한다.

반-Grokking 이 난 시도(`anti_grok` 1)는 후보에서 빼지 않고 표시한다. 선택 결과는 Gate 2.5 사전등록 문서에 시도 번호 · 값과 함께 동결한다.

## 4. $S_{\max}$

§12B-5: $S_{\max}$ ≥ max(5 × R1 의 $T_{grok}$, 100K). Gate 2 의 R1 은 최대 6,900 스텝이므로 5배는 34,500 이고, 하한 100K 가 정한다. P1 에서 고른 설정의 중도절단 비율이 30% 를 넘거나 고른 설정의 $T_{grok}$ 이 50K 를 넘으면 Gate 2.5 에서 예산을 늘리는 안을 올린다 (P2 의 저밀도 쪽이 더 늦을 수 있다).

### 8.3 관찰 (84회 전체)

- **wd 가 가장 크게 갈랐다.** wd 1.0 은 42회 중 33회가 Grokking 을 확정했고 $T_{grok}$ 중앙값 6,000, wd 0.1 은 13회 · 중앙값 24,300 이다.
- **lr 이 크면 암기가 늦고 Train 붕괴가 많다.** $T_{mem}$ 중앙값 lr 1e-4 · 3e-4 · 1e-3 = 300 · 500 · 1,400. Train 정확도가 0.99 이상에서 0.5 아래로 떨어진 횟수 합은 36 · 48 · 49.
- **init 효과는 아키텍처마다 다르다.** 전체로는 0.02 쪽 25/42, 1/√d 쪽 21/42 가 확정했다. B-3 · B-5 는 1/√d 설정을 골랐다.
- **중도절단 38회 중 15회는 예산이 아니라 불안정이다.** Val 이 0.95 를 넘었지만 지속 창 동안 유지하지 못했다. Gate 2.5 에서 $S_{\max}$ 와 지속 창 기준을 같이 본다.
- **B-6 해시 Router 는 거의 일반화하지 못했다.** 11/12 가 Val 최고 0.09~0.64 에 머물렀고, 같은 구조의 학습 Router(Cross-Model)는 7/12 가 후보다.
- **B-5 는 wd 0.1 에서 출력이 무너졌다.** 6회 중 4회가 Train · Val 모두 우연 수준(Val 0.0074 = 정답 분포의 최빈값만 맞힘, loss ≈ ln 97 = 4.57)으로 끝났고 회복하지 않았다. h03 · h09 (lr 1e-3) 는 첫 평가(100 스텝)부터, h02 는 17,300 스텝(직전 Val 0.92), h08 은 26,100 스텝에서다. NaN 은 없다 (loss 4.57 로 유한). 원인은 확인하지 않았다.
- 반-Grokking 표시 16회. 선택 중에는 B-2 h04 하나이고, 관측 기간 끝 Val 이 0.225 다.

### 8.4 Gate 2.5 에 올릴 것

1. **B-2 h04**: 반-Grokking 으로 끝 Val 0.225. 규칙대로 골랐지만 다음 후보 h05 ($T_{grok}$ 8,400, 끝 Val 1.000, 역시 반-Grokking 표시) 와 비교해 정한다.
2. **경계 선택 B-1 h05 · B-4 h06**: 간격이 기준 1,000 과 같다. 기준을 그대로 둘지.
3. **B-6**: 후보 1개, $T_{grok}$ 49,100 (4절의 50K 기준 바로 아래). 본 실험에서 $S_{\max}$ 를 늘리거나 해시 Router 쪽 격자를 넓힐지.
4. **중도절단 비율**: 4절의 30% 기준은 '고른 설정' 에 대한 것이지만 Seed 1개라 잴 수 없다. 아키텍처 전체로는 B-2 58% · B-6 92% · B-5 50% · Cross-Model 42% 다. 불안정형 중도절단(15회)을 보고 지속 창 기준을 다시 볼지.
5. **B-5 wd 0.1 붕괴**: 고른 설정(wd 1.0)과 무관하지만, 본 실험에서 wd 를 바꿀 일이 있으면 먼저 원인을 본다.

## 9. Gate 2.5 결정 — P1 선택 확정 (2026-11-28, 사람 결정)

8.4절 안건 다섯 가지를 사람과 정했다. 모두 권장안이다. 판단 근거는 기록된 평가 곡선(`experiments/runs/<run_id>/metrics.parquet`)으로 다시 계산했고 학습은 새로 하지 않았다 (안건 5 진단만 저장소 밖에서 2,000 스텝 × 2회).

### 9.1 선택 규칙 수정 (3절을 대신한다)

지연 Grokking 후보는 다음을 **모두** 만족하는 시도다.

1. $T_{grok}$ 이 확정됐고 $T_{grok} - T_{mem} \ge 1{,}000$ (3절 그대로)
2. **반-Grokking 표시(`anti_grok` 1)가 없다** (안건 1). 3절의 '빼지 않고 표시만' 을 바꾼다. Grokking 뒤 다시 외우기 상태로 돌아가는 설정은 P2 기준선으로 쓸 수 없다
3. **간격 중간 지점 $\lfloor (T_{mem}+T_{grok})/2 \rfloor$ 의 Val < 0.5** (안건 2). 외우자마자 Val 이 같이 오르는 점진형을 빼고, 정체한 뒤 뛰는 전이만 남긴다

후보 중 $T_{grok}$ 최단을 고르는 것은 그대로다. 7종 모두에 같은 규칙을 적용했다.

- 이 선택을 Gate 2.5 사전등록에 동결한다.

### 9.3 B-6 (안건 3)

h12 를 고르고 $S_{\max}$ 는 다른 아키텍처와 같게 둔다. B-6 은 'Router 학습 효과' 대조군이고, 해시 Router 가 일반화를 어렵게 하는 것 자체가 비교 대상이다. 중도절단은 생존 분석으로 다루고(기획서 §12B), 탐색 예산을 아키텍처마다 같게 둔다는 원칙(§12B-6, [30])을 지킨다. 결과 보고 때 '약한 대조군 (P1 후보 1/12)' 으로 표시한다.

### 9.4 지속 창 (안건 4, P2 부터 적용)

- 지속 창을 max(5,000, min(0.5 × 후보, 20,000)) 으로 바꾼다. 늦게 95% 를 넘는 조건일수록 창이 길어져(94K 에 넘으면 47K) 예산 안에 확인할 수 없었다. 임계 밀도 근처는 늦게 Grokking 할 가능성이 커서 생존 곡선이 한쪽으로 치우친다.
- $S_{\max}$ 에서 후보가 확인 중이면 창이 끝날 때까지만 더 학습한다 (최대 +20,000). $T_{grok}$ 은 여전히 $S_{\max}$ 안의 후보 시점이므로 예산 규칙(4절)은 그대로다.
- 84회 재판정: 확정 46 → 53회, $S_{\max}$ 에서 확인 중 12 → 5회 (연장하면 판정), 반-Grokking 16회 그대로. 창을 5,000 으로 고정하는 안은 확정 57회지만 반-Grokking 이 22회로 늘어 버렸다. 세 안 모두 9.2 선택은 같다.
- P1 의 기록(원장 · summary)은 바꾸지 않는다. `src/training/early_stop.py` 수정은 P2 대기열 전에 따로 한다.

### 9.5 B-5 wd 0.1 붕괴 (안건 5)

짧게 진단했다 (TROUBLESHOOTING T-014). bf16 · fp32 모두 같게 재현되어 정밀도 문제가 아니다. 몸통 가중치는 weight decay 만큼만 줄고 출력층만 바뀌어, 몸통으로 가는 기울기가 사실상 0 이다. 원인은 확인하지 않았다. 고른 설정(wd 1.0)에는 없으므로 진행하고, P2 에서 다시 나오면 원인부터 본다.
